# Alpha Disposable-Account Preparation Checklist

Complete this entire checklist before the first Session B invitation. Never use a learner's real email or password (`docs/alpha-recruitment-and-consent.md`) — only facilitator-provisioned, disposable test addresses.

- [ ] Confirm `GET https://stemforge-6an8.vercel.app/api/health/ready` reports every category `ok`, checked the same day.
- [ ] Provision one disposable email address per expected Session B participant (a facilitator-controlled mailbox with clear plus-addressing or an equivalent naming scheme, e.g. `stemforge-alpha+b01@…`), never a learner's real address.
- [ ] Dry-run one full sign-up → email confirmation → sign-in → guest-progress import → sign-out cycle on a spare account **before** any learner session, so the facilitator has seen the real flow once, not for the first time in front of a learner. This dry run doubles as the outstanding credentialed authenticated production smoke pass named in `STEM_FORGE_ALPHA_READINESS.md` §1/§6 — record its outcome in `docs/alpha-go-no-go-record.md`.
- [ ] Record each provisioned test account's address (not password) against the session ID it's reserved for, in `docs/alpha-device-allocation.md`.
- [ ] Confirm no test account is reused across two different learners within the same Alpha run (each learner's B2–B7 evidence must be theirs alone).
- [ ] After Alpha concludes: sign out of every test account on every device used, and use the account page's "Remove this account's progress from this browser" and remote learning-data erasure flow (per `STEM_FORGE_ACCOUNT_DATA_AND_SHARED_DEVICE_SAFETY.md`) to clean up synthetic evidence, rather than leaving it live indefinitely.
